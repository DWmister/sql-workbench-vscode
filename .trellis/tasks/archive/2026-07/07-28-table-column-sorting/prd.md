# 0.2.7 表结构字段排序

## Goal

当表字段较多时，让用户能在只读表结构 Columns 页签快速按字段名定位目标字段，同时保留数据库定义顺序作为默认视图。

## Background

- 当前表结构页直接按 `ColumnInfo.ordinal` 对应的数据库定义顺序渲染全部字段。
- Columns 表格已有 Name、Type、Length、Comment、Nullable、Primary Key、Default 列，但没有排序入口。
- 字段数据已经随页面一次性加载，排序不需要重新请求数据库。
- 本能力已确认归入 0.2.7；字段搜索、表名搜索等候选能力尚未确认进入本任务。

## Requirements

### R1. 默认顺序

- 首次打开表结构以及切换到另一张表时，字段顺序必须与数据库返回的原始定义顺序一致。
- 不能为了提供排序而改变 Schema inspector、DDL 或结构树中的字段顺序。

### R2. 字段排序

- 仅 Name 表头提供明确、可发现的排序入口；Type、Length、Comment、Nullable、Primary Key、Default 表头保持静态。
- 点击 Name 表头时按“数据库原始顺序 → 字段名升序 → 字段名降序 → 数据库原始顺序”循环，并显示当前排序方向。
- 排序必须对整行生效，字段类型、注释、主键、默认值等信息始终跟随对应字段。
- 字段名排序忽略大小写，并以原始字段顺序作为同名时的稳定次序。
- 用户可通过第三次点击 Name 表头恢复数据库原始顺序。

### R3. 兼容性与边界

- 排序仅在 Webview 已加载的数据中进行，不增加数据库请求。
- 表结构继续保持只读，不增加任何结构写入能力。
- DDL 页签的加载、复制、刷新和重试行为不变。

## Acceptance Criteria

- [x] AC1：首次打开 Columns 页签时，字段保持数据库定义顺序。
- [x] AC2：用户可将字段名切换为升序和降序，字段整行数据保持正确对应。
- [x] AC3：用户可恢复原始字段顺序，切换表后也回到原始顺序。
- [x] AC4：排序状态有可访问的文本或 ARIA 表达，不只依赖颜色。
- [x] AC5：排序不会发送数据库请求，也不影响 DDL 页签与只读边界。
- [x] AC6：自动化回归覆盖原始、升序、降序、恢复原序和切换表重置。

## Out of Scope

- 字段搜索或过滤。
- 数据库树表名搜索。
- 查询历史。
- 多表通配符结果字段注释。
